# Design: Frontend Route Code Splitting Performance

## Current Evidence

M14 合入后的生产构建基线为单个主包 605.54 kB、gzip 167.31 kB，超过默认 500 kB 警告阈值。`apps/web/src/App.tsx` 当前静态引入买家、卖家、员工页面。实施开始时必须在当时的 `origin/main` 和固定 Node/npm 环境重新采集基线；若数值变化，保留 M14 基线并解释差异，不能覆盖历史证据。

## Loading Boundaries

保留一个最小公共启动层，用于运行时配置、路由入口、必要的错误边界和身份无关样式。买家、卖家、员工三个身份壳分别使用动态导入；每个身份内部再以路由或功能页为边界拆分只有在访问时才需要的页面。共享合同、传输和 UI 代码由构建器安全复用，不手工复制为三个版本。

第一优先级是停止一个身份下载其他身份的业务页面；第二优先级才是按实测拆分同一身份的重页面。避免把大量页面重新汇总到一个人工 `index` 导出后抵消动态边界，也不为了制造更多小文件而拆分每个微小组件。

## Security and Correctness

按需加载不能改变服务器权限是真值的原则。`CustomerSessionBoundary`、`StaffSessionBoundary`、密码强制修改和 Personal DENY 等受控边界必须在敏感页面渲染前完成；加载占位不得显示上一身份的缓存、客户编号、内部利润或其他敏感内容。身份切换、401/403、退出登录和 Staff authorization version 变化仍须清理对应缓存。

直接访问买家、卖家、员工深层链接和刷新页面必须可用；加载失败使用中文提示和显式重试，不无限刷新。加载状态应可被屏幕阅读器识别，并避免产生明显布局跳动。

## Performance Evidence

在同一提交、同一依赖锁和同一构建环境记录：

- 初始入口及每个动态分包的压缩前与 gzip 大小；
- 买家、卖家、员工代表性首个受保护页面的冷启动网络请求、传输字节和可交互/主要内容出现时间；
- 深层链接首次访问及身份内首次导航到重页面的数据；
- 优化前后差异、测量工具、设备/网络模拟和至少三次运行的中位数。

目标是让初始入口不再超过 500 kB 默认阈值，并显著减少三类身份各自冷启动所需 JavaScript；任何超过 500 kB 的单一分包都必须说明依赖归因并进一步拆分或形成明确 Production GO 阻断。不得仅提高警告阈值、关闭 source map 或展示热缓存数据冒充完成。

## Verification and Rollback

组件和浏览器测试覆盖异步加载成功、失败重试、直接深链、登录/退出、401/403、缓存隔离以及买家/卖家/员工互不泄漏。运行完整前端测试、类型检查、生产构建、OpenSpec Strict 和 Implementation Verify。回滚只还原加载边界，不改 API、数据库或生产配置。
