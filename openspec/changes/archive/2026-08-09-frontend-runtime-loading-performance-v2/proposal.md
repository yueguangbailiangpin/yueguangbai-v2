# Change Proposal: Frontend Runtime Loading Performance V2

## Why

现有身份级拆包已经把生产入口从 650,256 B 降至约 245 kB，但老板在本地测试网址实际使用买家端和卖家工作台时仍感到卡顿。复测表明接口通常只需 1–24 ms，主要体感来自两个前端因素：测试网址仍由 Vite 开发服务器发送大量未压缩模块；卖家默认工作台还静态携带只在“提交产品/需求”页面需要的表单与文件上传依赖。

## What Changes

- 提供仓库内、可重复的一键本地生产式预览：先构建正式静态资源，再用同源匿名测试数据提供买家、卖家和员工演示入口。
- 将买家下单指引及其受控图片读取依赖从默认买家首页拆为按需加载模块。
- 将卖家提交产品/需求页面从默认卖家工作台拆为按需加载模块，避免首页下载文件上传和提交表单代码。
- 保留现有买家页面拆包、会话、强制改密、缓存隔离、权限和所有业务语义。
- 记录买家、卖家在开发预览与生产式预览下的请求/传输差异，以及修改前后生产分包和三次冷启动中位数。

## Out of Scope

- UI 视觉、字段、业务流程、API、Contract、Domain、Migration、权限、财务和文件 Audience 变化。
- 为了制造小包而拆分每个组件，或新增 UI/状态/性能框架。
- 预加载受保护身份页面；同环境实验未证明收益，因此不以额外请求换取推测性优化。
- Cloudflare、域名、D1/R2、飞书、Drive、MCP、真实 Secret、部署或任何生产写入。

## Migration

`NO_SCHEMA_CHANGE`。本 Change 只调整本地预览方式和前端模块加载边界。

## Rollback

删除本地生产式预览/测量脚本，并把买家指引页与卖家提交页恢复为静态导入即可。回滚不涉及数据库、API、权限或生产资源。
