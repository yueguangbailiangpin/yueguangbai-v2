# 月光白 V2 — 获客渠道隐私冻结规则

日期：2026-08-11

本文件是 `feature/frozen-portals-staff-acquisition-core` 的最新冻结补充。
如旧文档、旧预览、旧测试与本文件冲突，以本文件为准。

## 1. 核心业务规则

客户真实从哪里开发来，是月光白内部获客资产，不向普通业务员工公开。

普通业务员工包括：

- 售前 `pre_sales`
- 卖家对接 `seller_ops`
- 买家返款 `buyer_refund`

真实来源可见角色只有：

- 总管理员 `owner`
- 获客 `acquisition`

## 2. 售前 / 卖家对接只能看到匿名渠道编号

普通员工只能看到：

- 渠道1
- 渠道2
- 渠道3
- ……

普通员工接口和页面禁止返回或显示：

- 真实平台名称，例如小红书、知无不言、BOSS、Twitter/X
- 真实渠道名称
- 来源链接
- 人工开发 / Codex 自动开发来源方式
- 潜在线索评分
- 开发信号 Signal
- 谁发现的客户
- 内部来源备注

禁止仅通过 CSS/前端隐藏。后端 DTO 必须直接删除这些字段。

## 3. 总管理员 / 获客看到完整映射

内部渠道配置至少包含：

- 员工看到的匿名渠道编号：`staff_label`
- 真实平台：例如小红书、知无不言、TikTok
- 真实渠道名称：例如“小红书买家推广一组”
- 客户类型：买家 / 卖家
- 站点
- 对应接待微信：`intake_wechat_label`
- 状态

示例：

| 员工看到 | 真实平台 | 真实渠道 | 对应接待微信 |
|---|---|---|---|
| 渠道1 | 小红书 | 小红书买家推广一组 | 买家微信1 |
| 渠道2 | TikTok | TikTok 日本买家开发 | 买家微信2 |
| 渠道3 | 知无不言 | 知无不言卖家开发 | 卖家微信1 |

## 4. 一个渠道配置一个接待微信

数据库提供独立的 `acquisition_channel_privacy_profiles`。

新渠道创建后：

1. 自动获得一个匿名渠道编号，例如“渠道4”；
2. 在总管理员配置对应接待微信之前，售前 / 卖家对接不能看到或使用该渠道；
3. 配置完成后，该渠道才进入普通员工可用渠道列表。

当前实现把一个已配置的接待微信唯一绑定到一个渠道，避免同一微信同时代表多个来源导致归因混乱。

## 5. Prospect 交接也必须隐藏真实来源

总管理员 / 获客看到完整潜在线索：

- 真实来源
- 来源链接
- 人工 / Codex
- AI Score
- Signal
- 内部备注

交给售前 / 卖家对接以后，安全交接 DTO 只包含：

- 潜在线索 ID
- 买家 / 卖家类型
- 站点
- 匿名渠道编号
- 客户 / 公司名称
- 可用于接入的联系方式
- 交接状态

不包含真实开发来源。

## 6. 正式 Lead 也不得泄露真实来源

售前 / 卖家对接的正式线索 DTO 只返回：

- 客户信息
- 站点
- 匿名渠道编号
- 业务进度
- 当前负责人
- 普通业务备注

不得返回：

- `origin_mode`
- `origin_source_url`
- `origin_channel_name`
- `origin_staff_id`
- `prospect_id`

这些真实来源事实仍保留在数据库中，用于 Owner / 获客的统计和归因，但不通过普通员工 Lead API 返回。

## 7. 中文化冻结

员工后台用户可见业务文案全部中文化。

禁止普通员工页面显示以下产品术语：

- Buyer Intake
- Seller Intake
- Prospect
- Buyer Lead
- Seller Lead
- Marketplace
- ACTIVE / DISABLED
- HUMAN

统一显示为：

- 买家客户接入
- 卖家客户接入
- 潜在线索 / 待接入客户
- 正式买家线索
- 正式卖家线索
- 站点
- 正常 / 已停用
- 人工开发（仅 Owner / 获客可见）

`Codex`、`Cloudflare Access` 等正式产品名称可以保留，但周围业务说明必须中文。

## 8. 渠道来源归因仍永久保留

匿名渠道仅是权限视图，不改变真实业务归因。

数据库仍永久保存：

真实渠道 → 潜在线索 → 正式线索 → 正式客户 → 产品 / 预约 / 订单 → 利润

Owner / 获客仍可以统计：

- 每个真实平台产生多少客户
- 每个真实渠道产生多少客户
- Codex 与人工开发的效果
- 每个渠道的正式订单数
- 每个渠道的利润

普通员工只能看到与当前客户关联的“渠道N”。

## 9. 本地 Codex 验收必须包含

至少验证：

1. `pre_sales` 调用渠道接口时响应 JSON 不包含 `platform_name`、`display_name`、真实来源链接；
2. `seller_ops` 同样不可获得真实来源字段；
3. handoff 响应不包含 `source_url`、`origin_mode`、`ai_score`、Signal；
4. Lead 响应不包含 `origin_source_url`、`origin_mode`、`origin_channel_name`、`origin_staff_id`、`prospect_id`；
5. `owner` 和 `acquisition` 可以查看真实来源渠道；
6. 未配置接待微信的渠道不会出现在普通员工可用渠道列表；
7. 同一个接待微信不能同时绑定两个渠道；
8. 普通员工界面只显示“渠道N”；
9. 员工后台无遗留 Buyer Intake / Seller Intake / Prospect / Lead / Marketplace 等业务英文文案。
