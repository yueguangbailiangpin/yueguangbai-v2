# 历史订单表格「数据要求（字段内容）」文档

> 用途：卖家客户上传历史订单表格前，按本文件准备表头与数据格式。系统只接受符合本契约的表格；不符合的列会进入待确认（HOLD），不会自动改动你的数据。
> 当前版本基线：`数据订单汇总.xlsx`（数据母表）30 列契约，2026-08-16。

## 1. 上传前须知

- 表格建议使用 **XLSX 或 CSV**，第一行必须是表头（列名），表头必须与下表完全一致（名称、顺序可参考下表，缺列/多列会提示）。
- 金额一律填写**原始数字**（不要写公式、不要带货币符号、不要四舍五入说明），系统按来源快照保存，不做任何推算。
- 日期格式统一 `YYYY-MM-DD`（或 `YYYY/MM/DD`，系统可识别；纯数字日期请避免歧义）。
- 同一订单多行（多商品）允许；系统按订单号识别，不会重复导入。
- 图片列（聊天截图、订单截图等）本次**只登记计划，不读取图片内容**；请勿在表格里嵌图片文件。

## 3. 会被系统拦下（HOLD / quarantine）的情况

- 表头缺失或与契约不一致（缺列、多列、列名不同）。
- 订单号格式无法识别（既不是 Amazon/Rakuten/TikTok 格式）。
- 店铺/产品无法唯一归属到当前卖家组织（多卖家、无主）。
- 同一订单号出现在不同卖家名下（跨卖家冲突）。
- 金额列不是整数或含公式/货币符号。
- Marketplace 暂不支持（Rakuten / TikTok 当前为本地候选，正式导入前需另行确认）。

## 4. 上传后流程

```text
上传表格 → 只读解析 → 校验/HOLD 明细 → 预览报告（可导入行/问题行/财务摘要）
→ 人工确认 → 分批导入（幂等 + 断点续传） → 状态可查（批次/行级）
```

- 未确认前**不会写任何数据**；确认后仍可在批次内回滚，错误行用冲正处理，不直接覆盖。
- 历史金额是来源快照：系统不会根据当前政策重算你的历史利润/返款。
