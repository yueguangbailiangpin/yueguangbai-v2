# V2 安全模型

## 1. 私人微信

允许：

- 人工沟通；
- 人工发送门户链接；
- 人工选择必要截图上传；
- 在系统中记录沟通结论。

禁止：

- Hook；
- 非官方协议；
- RPA 自动控制；
- 批量自动加人；
- 自动读取私人聊天数据库；
- 全量聊天永久抓取；
- Agent 自动发送私人微信消息。

## 2. 数据最小化

只收集业务必需的数据。私人微信截图必须：

- 由员工主动选择；
- 关联明确客户/订单/任务；
- 标记用途和可见范围；
- 支持配置保存期限；
- 不默认永久保存；
- 支付截图应尽量遮盖无关账户和余额信息。

生产前需完成正式隐私告知和保存期限决定。

## 3. Secrets

Secrets 只存于本地安全环境或 Cloudflare Secret，不进入 Git。

必须扫描：

- API Key；
- GitHub Token；
- OAuth Secret；
- Session Secret；
- 飞书 App Secret；
- 真实账号和密码；
- 旧资源 ID 和旧域名。

日志不得输出 Secret 或完整 Session。

## 4. Session

- 客户 Session 签名且可撤销。
- 员工飞书 Session 短期有效。
- 密码哈希使用经过测试的 Workers 兼容算法。
- 登录限流按 IP 和账号组合。
- 账号不存在时执行等价密码验证成本，减少枚举。
- 安全变更递增 session_version。

## 5. 访问控制

- 服务端强制校验，前端隐藏不是权限。
- 客户资源按组织/买家主体和 Marketplace 过滤。
- 卖家店铺范围进入 SQL Scope。
- 字段使用显式白名单。
- 无权资源返回 404。
- 图片读取再次检查主体、资源和图片类型。

## 6. 财务

- 金额使用固定点整数。
- 已完成事实不可变。
- 每次更正有原事实、冲正和新事实。
- 财务导出记录审计事件。
- 普通客服不能执行财务写入。
- 财务命令必须版本化和幂等。

## 7. 供应链与部署

- 固定依赖版本或锁文件。
- CI 执行类型检查、测试、构建和 Secret 扫描。
- 部署命令默认 dry-run。
- 生产部署、Migration 和数据导入必须单独授权。
- 不从旧仓库复制 `wrangler.jsonc`。
- 不使用旧生产 D1/R2。

## 8. 审计

记录：

- 员工身份；
- 客户身份；
- 请求 ID；
- 业务命令；
- 状态前后；
- 金额前后；
- Idempotency-Key；
- 版本；
- 结果；
- 时间；
- 失败类别。

日志和审计事件不得保存密码、Session、Secrets 或不必要的完整截图内容。
